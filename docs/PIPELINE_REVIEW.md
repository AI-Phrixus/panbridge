# v0.5.5 磁碟預取流水線（2026-10-02）

## 改變的機制

舊模式逐檔「下載 → 上傳 → 下一檔」。新雲端搬運模式維持 1 個文件下載器與
1 個文件上傳器，兩階段可重疊；最多 3 個在途文件（包括等待與上傳），暫存
控制預算預設 64 GiB。單文件下載仍使用原有最多 6 條 Range 連線及同一 `.part`
原地寫入，不因流水線倍增連線，也沒有額外拼接文件或新增 aria2/rclone 常駐程序。

同一 Worker 跨任務共享文件數、磁碟預算與階段信號量。新文件先預約完整容量，
磁碟剩餘量扣除其他未實際配置的預約，再保留設定的 2 GiB 安全空間（最低
512 MiB）。稀疏文件的 logical size 與 allocated blocks 分開計算。失敗後保留的
文件仍計入實際暫存預算，不把釋放 lease 當成清理文件。

超過 64 GiB 的單文件可獨占，仍必須物理容量足夠；未知大小文件亦獨占，回呼
檢查整個暫存根目錄與安全空間。64 GiB 是控制預算而非每一瞬間的絕對上限：
未知大小可能在偵測前短暫多寫一批資料。已存在的超額暫存不會被擅自刪除。

## 恢復與完整性

- 完整下載並檢查大小後才上傳，不把尚未完成的文件交付 Google。
- 完整預取文件等待時沿用 `queued` 狀態和本機路径，重啟可直接上傳；半文件從既有斷點恢復。
- done、skipped、failed 不自動重播；Google 帳號綁定、加密上傳 checkpoint、完成大小／ID 與去重門檻不變。
- 上傳成功先持久化 done，再清理本批傳輸暫存；不清理 Mac 備份或其他任務。
- pause/delete/cancel 等待全部子工作退出；登入失效、永久拒絕或容量問題停止流水線，不新增任務／公開分享。
- 原子狀態條件防止晚到回呼復活已暫停／刪除任務。速度分別聚合上下行，舊續傳 bytes 不算新流量。

## 測試證據與限制

本機完整回歸 213 passed；20 項新流水線測試包含重疊、3 件上限、下載／上傳
各 1、控制操作 drain、硬失敗、續傳、不重播、跨任務预算、稀疏文件、失敗暫存、
未知大小與速度基準。UI／入口共 25 項邏輯測試、ops 9 項安全測試通過。
紅軍找到並修復未知大小漏算既有失敗暫存的漏洞；復審 20 項通過。

藍軍独立驗證遠端缺 ID、缺 size、大小不符及下載截斷均拒絕標記完成、保留暫存。
4 文件 × 4096 bytes、每次下載／上傳各延遲 0.1 秒的受控離線模擬：serial
0.8275 秒、pipeline 0.5312 秒，約節省 35.8%；兩種模式各 4 件 done，內容
SHA-256 全同。這只證明階段重疊機制，不是真實夸克 CDN／Google 加速倍率。
藍軍沙盒未允許本機 TCP bind，該 socket 測試跳過；主程序本機完整測試已通過該項。

生產部署與真實重疊驗收見 [STATUS.md](STATUS.md)。未做同來源／同文件改動前後
基準，不宣稱 1.56 倍等真實網速；長時間網路故障、Google 備份全量 SHA-256、
Windows/VLC/Infuse 播放仍是獨立門檻。

## 設定與復原

`TRANSFER_PREFETCH_FILES=3`，`TRANSFER_STAGING_BYTES=68719476736`。
`TRANSFER_PREFETCH_FILES=1` 可退回逐檔串行；LocalSink 本來就保留串行。
沒有 DB schema 變更；如需撤回，停服務、還原本次部署的舊程式，再啟動，
不可把舊 DB 備份覆蓋已新增的交付紀錄。不要對既有 failed 擅自按 resume/retry，
因為這些 API 會重新排隊失敗文件。

設計參考：[OpenList-Worker](https://github.com/OpenListTeam/OpenList-Worker) 的
驅動／直鏈分工、[aria2](https://aria2.github.io/manual/en/html/aria2c.html) 的
單文件連線與多文件排程區分、[rclone](https://rclone.org/docs/) 的有界傳輸資源。
採設計原則自行實作，沒有複製其程式碼或新增執行程式依賴。
