# UI 2：當前項目列表與序號

2026-10-02。只修改介面與可選視圖設定，不修改任務資料或下載程式。

## 語義

- 使用者要求重新排序、從頭開始，解釋為列表從序號 1 開始，不是清空下載、重播文件或重設資料庫。
- 以內部任務 ID 升冪代表建立順序，對符合當前視圖的任務產生 `displayNumber`。序號是可見列表位置，刪除任務後可能重新排列，不是永久識別碼。
- 細節連結和所有控制請求仍使用內部 ID。例：顯示 #1 的 `/tasks/16` 及暫停 API 仍操作 16，絕不將 1 當成資料庫 ID。
- 視圖不顯示 OneDrive、已軟刪除、重複內部 ID 或設定起点前的任務。不能按標題或分享網址去重，因為不同選檔、目標或用途可能合理共存。
- 歷史記錄保留作來源與備份校驗；這是呈現範圍，不是授權、安全隔離或資料清除。已登入 API 仍可讀歷史資料。

## 部署設定

可選 `web/static/task-view.json`：

```json
{"schema":1,"first_job_id":1}
```

範例文件 `web/static/task-view.example.json` 納入 Git，實際設定在 `.gitignore` 中。此公開靜態設定不含秘密。新安裝缺少設定時從 1 起；只有 GET 的 404 可視為缺少設定，500、錯誤 schema 或非法起點須顯示錯誤，不靜默混入歷史項目。此部署起點為 16，現在只有 #16／#18 被呈現為 #1／#2；以後合法新任務仍可出現。

詳情頁先從同一視圖解析序號；舊項目直達 URL 顯示「舊項目記錄」，不載入其文件或顯示重新搬運控制，不誤稱為當前 #1。資料庫 ID 沒有改變，因此既有監控與備份映射不需迁移。
